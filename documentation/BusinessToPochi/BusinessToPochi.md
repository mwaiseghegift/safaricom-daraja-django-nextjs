class="MuiBox-root css-rem0j2"><div class="docs_tableContainer__qBw9Z MuiBox-root css-1oyv9ht"><h2 id="overview">Overview</h2>
<p>B2Pochi API is a version of Business to Customer API used to make payments from a Business to Customers business wallet locally known as pochi la biashara(microSME)</p>
<h2 id="how-it-works">How It Works</h2>
<ol>
<li>The Merchant (Partner) prepares and sends a payment request to the M-PESA B2POCHI API endpoint.</li>
<li>The API Management Platform validates, authorizes, and authenticates the request, forwards it to M-PESA, and sends an acknowledgment to the Merchant.</li>
<li>M-PESA validates the request and initiator details, then processes the transaction.</li>
<li>M-PESA sends the transaction response to the Merchant via the specified callback URL.</li>
<li>The Customer receives an SMS notification confirming the payment.</li>
</ol>
<blockquote>
<p><strong>Note:</strong> To go live and use the API in production, you must apply for a Bulk Disbursement Account and obtain a B2C Short Code or you convert your existing pay bill/till number to one account(can receive and disburse). Apply for the Bulk Disbursement Account/one account here <a href="https://www.safaricom.co.ke/business/sme/m-pesa-payment-solutions">https://www.safaricom.co.ke/business/sme/m-pesa-payment-solutions</a>.</p>
</blockquote>
<h2 id="getting-started">Getting Started</h2>
<h3 id="prerequisites">Prerequisites</h3>
<ol>
<li>Create a Daraja Account on <a href="https://daraja.safaricom.co.ke/">Safaricom Developer Portal</a>.</li>
<li>Create a sandbox app in the portal to get API credentials.</li>
<li>Retrieve Consumer Key &amp; Consumer Secret from your sandbox app on <a href="https://daraja.safaricom.co.ke/dashboard/myapps">My Apps</a>.</li>
<li><strong>Test data:</strong> Available on the simulator section.</li>
<li><strong>Initiator Username:</strong> This is the API operator's username as set on the portal when the user was created. For Sandbox users, the username is already created and assigned to them and is available on the test credentials page as InitiatorName.</li>
<li><strong>Initiator Password:</strong> This is the password assigned to the API operator after being created by the Business Administrator. For Sandbox users, this is available as InitiatorPassword on the test credentials page.<br>
<strong>Note:</strong> The password should be limited to specific special characters such as #, &amp;, %, and $. Other characters might cause issues, and the password may not be accepted. For example, using a <code>(</code> or <code>)</code> character will not be accepted. In addition, @ is not a special character on M-Pesa; it is treated as a normal character.</li>
<li><strong>Public Key Certificate:</strong> This certificate is used to encrypt the Initiator's plaintext password for use in API calls. It is provided for both Sandbox and Production clients on the portal. You need to encrypt the password using your API language or use the test credentials section, which offers the capability to encrypt your password.</li>
<li><strong>Live M-PESA B2C shortcode, Paybill/till number:</strong> For Go Live, you need a shortcode or number that can receive and disburse funds (one account) with Business Admin/Manager operators created.</li>
<li><strong>Pochi la Biashara:</strong> The receiving party the B2C organization is disbursing to must have customer business wallet locally known as pochi la biashara or Micro SME</li>
</ol>
<h3 id="good-to-know">Good to Know</h3>
<p>This API is asynchronous. You can consume this API over the internet, a virtual private network or Multiprotocol Switch.</p>

<h2 id="account-types-in-c2b-organization">Account Types in C2B Organization</h2>
<ol>
<li>
<p><strong>MMF/WORKING/M-PESA ACCOUNT FOR ORGANIZATION</strong></p>
<ul>
<li>When an organization wants to make a business withdrawal, the funds are transferred to this account before the withdrawal request is made.</li>
</ul>
</li>
<li>
<p><strong>UTILITY ACCOUNT</strong></p>
<ul>
<li>Payments from customers are credited into the utility account.</li>
</ul>
</li>
<li>
<p><strong>CHARGES PAID ACCOUNT</strong></p>
<ul>
<li>For payments received from customers, depending on the tariff, a charge is levied on the Organization or is split between the organization and the customer. The charges paid account is debited and always accrues a negative balance which has to be settled before an organization can make a withdrawal request.</li>
</ul>
</li>
<li>
<p><strong>ORGANIZATION SETTLEMENT ACCOUNT</strong></p>
<ul>
<li>This account does the calculations for the organization operator when s/he initiates a revenue settlement. This account settles the charges paid account and then moves the balance from the Utility Account to the MMF account automatically. You will notice that the transaction type “Move funds from Utility to MMF” is no longer available as the revenue settlement process takes care of this.</li>
</ul>
</li>
</ol>

<h3 id="faqs">FAQs</h3>
<ol>
<li>
<p><strong>How do I apply for a live pay bill number, till number, or B2C Account?</strong><br>
Apply by emailing <a href="mailto:M-PESABusiness@Safaricom.co.ke">M-PESABusiness@Safaricom.co.ke</a>.</p>
</li>
<li>
<p><strong>Why am I not receiving callbacks on my B2Pochi ResultURL?</strong><br>
Ensure your ResultURL is valid and accessible over the internet. Use a publicly accessible IP address or domain name for your callback endpoint.</p>
</li>
<li>
<p><strong>What should I do if I encounter an invalid access token error?</strong></p>
<ul>
<li>Ensure the access token has not expired (tokens expire hourly).</li>
<li>Use the correct consumer key and consumer secret to generate the access token.</li>
</ul>
</li>
<li>
<p><strong>Can I use my actual B2C short code on the Daraja portal simulator?</strong><br>
No. The simulator supports sandbox test short codes only. Use your code/application or a REST client (e.g., Postman) for actual short code testing.</p>
</li>
<li>
<p><strong>How do I know if the B2Pochi request is successful?</strong><br>
The API is asynchronous. You receive an acknowledgement after making the request, but the final result is sent to your specified ResultURL. A successful transaction has <code>ResultCode</code> 0.</p>
</li>
<li>
<p><strong>Is there a test environment for B2Pochi API?</strong><br>
Yes. Use the sandbox environment and test credentials provided on the Daraja developer portal. You can test via the simulator, your application, or any REST client.</p>
</li>
<li>
<p><strong>Why am I getting a balance insufficient error, yet I have money in my B2C account?</strong><br>
B2C transactions are debited from the Utility account. Ensure sufficient funds are available in the Utility account.</p>
</li>
<li>
<p><strong>How do I move funds from MMF/Working account to Utility account for B2C disbursement?</strong></p>
<ul>
<li>Log in to the M-PESA portal as a Business Web Operator.</li>
<li>Go to My Functions &gt; Initiate Transaction.</li>
<li>Select "Move Funds from MMF Account to Utility Account".</li>
<li>Enter the required details and submit.</li>
<li>The transaction must be approved by another operator via My Tasks &gt; Group Task.</li>
</ul>
<p>This can also be automated using the B2B API.</p>
</li>
<li>
<p><strong>Can I automate the funds transfer from MMF/Working account to Utility account?</strong><br>
Yes. Use the B2B API with CommandID <em><strong>BusinessTransferFromMMFToUtility</strong></em>. Contact <a href="mailto:apisupport@Safaricom.co.ke">apisupport@Safaricom.co.ke</a> for whitelisting.</p>
</li>
<li>
<p><strong>What are the minimum and maximum limits for B2Pochi transaction amounts?</strong></p>
<ul>
<li>Minimum: Ksh 10</li>
<li>Maximum per transaction: Ksh 250,000</li>
<li>Maximum account balance: Ksh 500,000</li>
<li>Maximum daily transaction value: Ksh 500,000</li>
</ul>
</li>
<li>
<p><strong>Which API role is required for B2Pochi requests?</strong><br>
Assign the <em><strong>ORG B2C API initiator</strong></em> role to your API user.</p>
</li>
<li>
<p><strong>API user is showing pending active status; how do I activate it?</strong><br>
Set the API user password via the M-PESA portal using a user with the Set Restricted ORG API PASSWORD role.</p>
</li>
<li>
<p><strong>Why am I getting "initiator information is invalid" error?</strong><br>
Possible reasons:</p>
<ul>
<li>Wrong API user username</li>
<li>Incorrectly encrypted API user password</li>
<li>Wrong algorithm or certificate used for password encryption<br>
Use the encryption tool at <a href="https://developer.safaricom.co.ke/TestCredentials">developer portal</a>.</li>
</ul>
</li>
<li>
<p><strong>Why am I getting "security credential is locked" error?</strong><br>
Multiple failed login attempts lock the password. The Business Administrator can unlock it on the M-PESA portal. Ensure the correct password is used.</p>
</li>
<li>
<p><strong>How do I resolve "Invalid API call as no apiproduct match found" error?</strong></p>
<ul>
<li>Ensure the B2C product is enabled on your Daraja application (for production).</li>
<li>Verify you are calling the correct API endpoint.</li>
</ul>
</li>
<li>
<p><strong>Do I need a passkey for B2Pochi?</strong><br>
No. Passkey is only required for M-PESA Express/STKpush API requests.</p>
</li>
<li>
<p><strong>Why is the B2C product missing when I try to Go Live with my pay bill?</strong><br>
Your pay bill does not have permission for B2C payments. Apply for a B2C or one account short code at <a href="https://m-pesaforbusiness.co.ke/">https://m-pesaforbusiness.co.ke/</a>.</p>
</li>
<li>
<p><strong>Can I reverse a B2Pochi transaction using the Reversal API?</strong><br>
No. Reversal of B2C transactions via API is not supported. This must be done manually on the M-PESA portal.</p>
</li>
<li>
<p><strong>Why am I getting "Bad Request - Invalid InitiatorName" error?</strong><br>
Possible causes:</p>
<ul>
<li>Wrong Content-Type (should be application/json)</li>
<li>Incorrect parameter name</li>
<li>Invalid or missing InitiatorName value</li>
</ul>
</li>
<li>
<p><strong>Can I have both B2Pochi and C2B on my Daraja application?</strong><br>
Yes, if both functionalities are enabled for your short code on M-PESA.</p>
</li>
<li>
<p><strong>Which operator can create an API user?</strong><br>
Only the Business Administrator can create API users. Any web user with Set Restricted ORG API PASSWORD role can set the password.</p>
</li>
<li>
<p><strong>Do I need to generate the security credential for every B2Pochi request?</strong><br>
No. The same security credential can be reused for multiple requests.</p>
</li>
<li>
<p><strong>Do I need to manually approve the B2Pochi request after initiating via API?</strong><br>
No. Manual approval is not required.</p>
</li>
