class="docs_tableContainer__qBw9Z MuiBox-root css-1oyv9ht"><h2 id="overview">Overview</h2>
<p>The M-PESA Account Balance API by Safaricom enables organizations to programmatically check their M-PESA account balances. This is essential for automating financial processes, monitoring account status, and ensuring sufficient funds for operations.</p>
<p><strong>Key Features:</strong></p>
<ul>
<li><strong>Real-time Balance Inquiry:</strong> Instantly retrieve your M-PESA account balance.</li>
<li><strong>Secure Access:</strong> Authentication and authorization ensure only permitted entities access the balance.</li>
<li><strong>Automated Responses:</strong> Receive automatic acknowledgments and responses to inquiries.</li>
</ul>
<h2 id="how-it-works">How It Works</h2>
<ol>
<li>
<p><strong>Request Setup and Submission:</strong><br>
• Action: The Organization configures the request with all necessary parameters.<br>
• Endpoint: The request is sent to <a href="https://sandbox.safaricom.co.ke/mpesa/accountbalance/v1/query">https://sandbox.safaricom.co.ke/mpesa/accountbalance/v1/query</a>.<br>
• Purpose: This step initiates the process of querying the account balance via the M-PESA system.</p>
</li>
<li>
<p><strong>Acknowledgment by Daraja:</strong><br>
• Action: Upon receiving the request, the API Management Platform (Daraja) performs several checks.<br>
• Validation: Ensures that all required parameters are present and correctly formatted.<br>
• Authorization: Confirms that the Organization has the necessary permissions to access the API.<br>
• Authentication: Verifies the identity of the Organization.<br>
• Response: Daraja sends a synchronous acknowledgment back to the Organization indicating that the request has been received and is being processed.</p>
</li>
<li>
<p><strong>Forwarding to M-PESA:</strong><br>
• Action: Daraja forwards the validated, authorized, and authenticated request to the M-PESA system for further processing.</p>
</li>
<li>
<p><strong>Acknowledgment by M-PESA:</strong><br>
• Action: M-PESA receives the request and performs initial validation.<br>
• Response: M-PESA sends an acknowledgment response back to the Organization, confirming receipt of the request.</p>
</li>
<li>
<p><strong>Internal Processing:</strong><br>
• Action: M-PESA processes the request internally. This involves verifying the details and preparing the account balance information.</p>
</li>
<li>
<p><strong>Response Callback:</strong><br>
• Action: Once processing is complete, M-PESA sends the account balance response to the Organization.<br>
• Method: The response is sent to the callback URL specified by the Organization in the initial request.</p>
</li>
<li>
<p><strong>Status Check on Failure:</strong><br>
• Note: If M-PESA is unable to deliver the callback (e.g., due to network issues), there are no automatic retries.<br>
• Action: The Organization can manually check the status of the transaction by querying M-PESA portal if the callback fails.</p>
</li>
</ol>
<blockquote>
<p><strong>Note:</strong> This API is asynchronous and can be accessed via the internet, VPN, or Multiprotocol Switch.</p>
</blockquote>
<h2 id="getting-started">Getting Started</h2>
<h3 id="prerequisites">Prerequisites</h3>
<ul>
<li>Create a Daraja Account on the <a href="https://daraja.safaricom.co.ke/">Safaricom Developer Portal</a>.</li>
<li>Create a sandbox app to obtain API credentials.</li>
<li>Retrieve Consumer Key &amp; Consumer Secret from <a href="https://daraja.safaricom.co.ke/dashboard/myapps">My Apps</a>.</li>
<li>Use test data from the simulator section.</li>
<li>For production, ensure you have a live pay bill/till number with Business Admin/Manager operators.</li>
</ul>
<h3 id="good-to-know">Good to Know</h3>
<p>This API is asynchronous and is used to check the status of various M-PESA transactions, including C2B, B2B, B2C, Reversal, and IMT.</p>
<h2 id="authentication">Authentication</h2>
<p>Generate an access token before making API calls. See the <a href="https://daraja.safaricom.co.ke/dashboard/apis?api=Authorization">Authorization API</a>. Token generation is automated in the simulator section.</p>

<h3 id="use-cases">Use Cases</h3>
<ol>
<li>
<p><strong>Financial Reconciliation</strong><br>
<em>Scenario:</em> A business needs to reconcile its daily transactions with its M-PESA account balance.<br>
<em>Process:</em> The organization schedules a balance query at the end of each business day to ensure all transactions are accounted for and reconciled with their internal records.</p>
</li>
<li>
<p><strong>Automated Payment Systems</strong><br>
<em>Scenario:</em> An e-commerce platform automates payments to vendors through M-PESA.<br>
<em>Process:</em> Before initiating payments, the platform queries the M-PESA account balance to ensure there are sufficient funds to cover all outgoing payments. If funds are insufficient, the platform triggers an alert for manual intervention.</p>
</li>
<li>
<p><strong>Fraud Monitoring</strong><br>
<em>Scenario:</em> A financial institution uses M-PESA for various transactions and needs to monitor fraudulent activities.<br>
<em>Process:</em> The institution sets up periodic balance checks to detect any unauthorized withdrawals or discrepancies in account balances, helping to identify potential fraud quickly.</p>
</li>
<li>
<p><strong>Cash Flow Management</strong><br>
<em>Scenario:</em> A retail chain manages its cash flow by monitoring the balance of multiple M-PESA accounts used across different branches.<br>
<em>Process:</em> The head office queries the balance of each branch’s M-PESA account at regular intervals to manage and allocate funds effectively, ensuring each branch has sufficient operating capital.</p>
</li>
<li>
<p><strong>Payroll Processing</strong><br>
<em>Scenario:</em> A company uses M-PESA to disburse salaries to its employees.<br>
<em>Process:</em> Before processing payroll, the company queries the account balance to confirm there are enough funds to cover the total payroll amount. If not, the finance team tops up the account accordingly.</p>
</li>
<li>
<p><strong>Bill Payments</strong><br>
<em>Scenario:</em> A utility company allows customers to pay bills via M-PESA and needs to monitor the received payments.<br>
<em>Process:</em> The company queries the account balance periodically to track the total payments received and ensure accurate recording in their financial system.</p>
</li>
</ol>

<h2 id="account-types-in-c2b-organization">Account Types in C2B Organization</h2>
<ol>
<li>
<p><strong>MMF/WORKING/M-PESA ACCOUNT FOR ORGANIZATION</strong></p>
<ul>
<li>When an organization wants to make a business withdrawal, the funds are transferred to this account before the withdrawal request is made.</li>
</ul>
</li>
<li>
<p><strong>UTILITY ACCOUNT</strong></p>
<ul>
<li>Payments from customers are credited into the utility account.</li>
</ul>
</li>
<li>
<p><strong>CHARGES PAID ACCOUNT</strong></p>
<ul>
<li>For payments received from customers, depending on the tariff, a charge is levied on the Organization or is split between the organization and the customer. The charges paid account is debited and always accrues a negative balance which has to be settled before an organization can make a withdrawal request.</li>
</ul>
</li>
<li>
<p><strong>ORGANIZATION SETTLEMENT ACCOUNT</strong></p>
<ul>
<li>This account does the calculations for the organization operator when s/he initiates a revenue settlement. This account settles the charges paid account and then moves the balance from the Utility Account to the MMF account automatically. You will notice that the transaction type “Move funds from Utility to MMF” is no longer available as the revenue settlement process takes care of this.</li>
</ul>
</li>
</ol>

<h2 id="faqs">FAQs</h2>
<ol>
<li>
<p><strong>What is the M-PESA Account Balance Query API?</strong><br>
The M-PESA Account Balance Query API allows organizations to programmatically check the balance of their M-PESA accounts. It provides a secure and automated way to retrieve real-time account balance information.</p>
</li>
<li>
<p><strong>Who can use the M-PESA Account Balance Query API?</strong><br>
Any organization with an M-PESA account that has registered for access to the Safaricom Daraja API platform can use this service. The organization must have the necessary permissions and credentials to authenticate and authorize the API requests.</p>
</li>
<li>
<p><strong>What information is required to make a balance query request?</strong><br>
To make a balance query request, you need the following information:</p>
<ul>
<li>The short code of the M-PESA account.</li>
<li>A valid access token for authentication.</li>
<li>The command ID, typically set to AccountBalance.</li>
<li>The party A (the organization’s short code).</li>
<li>The identifier type, typically set to 4 (short code).</li>
<li>A callback URL to receive the balance response.</li>
<li>Remarks and queue timeout URL (optional).</li>
</ul>
</li>
<li>
<p><strong>How does the authentication process work?</strong><br>
Authentication is performed using OAuth 2.0. The organization must obtain an access token by sending a request to the OAuth endpoint with their client key and client secret. This access token is then used in the header of the balance query request to authenticate the organization.</p>
</li>
<li>
<p><strong>What is the typical response time for a balance query request?</strong><br>
The response time for a balance query request can vary depending on the network conditions and the load on the M-PESA system. However, the Daraja platform typically provides a synchronous acknowledgment within a few seconds, and the final account balance response is usually delivered within a few minutes.</p>
</li>
<li>
<p><strong>What happens if the callback URL is unreachable?</strong><br>
If the callback URL is unreachable or the response delivery fails due to network issues, M-PESA does not automatically retry the callback. The organization must manually query the transaction status using the unique transaction ID provided in the acknowledgment.</p>
</li>
<li>
<p><strong>Can I check the balance of multiple M-PESA accounts?</strong><br>
Yes, you can check the balance of multiple M-PESA accounts by sending separate balance query requests for each account. Each request must include the specific short code of the account you wish to query.</p>
</li>
<li>
<p><strong>Is the balance information provided in real-time?</strong><br>
Yes, the balance information provided through the M-PESA Account Balance Query API reflects the real-time balance of the M-Pesa account when the query is processed.</p>
</li>
<li>
<p><strong>What security measures are in place for the M-PESA Account Balance Query API?</strong><br>
The API uses OAuth 2.0 for secure authentication and authorization. All requests and responses are transmitted over HTTPS to ensure data encryption during transit. Additionally, the API checks for valid parameters and permissions to prevent unauthorized access.</p>
</li>
<li>
<p><strong>Can I automate balance checks?</strong><br>
Yes, organizations can automate balance checks by scheduling balance query requests at regular intervals. This can be useful for financial reconciliation, cash flow management, and other automated processes.</p>
</li>
<li>
<p><strong>What should I do if I receive an error response?</strong><br>
If you receive an error response, check the error code and message for details. Common issues include missing or invalid parameters, authentication failures, and authorization issues. Ensure that all required fields are correctly filled and that your access token is valid. If the issue persists, contact Safaricom support for assistance.</p>
</li>
<li>
<p><strong>How can I test the Account Balance Query API?</strong><br>
You can test the API using the sandbox environment provided by Safaricom. The sandbox environment allows you to simulate API requests and responses without affecting your actual M-PESA account. Use the sandbox endpoint <a href="https://sandbox.safaricom.co.ke/mpesa/accountbalance/v1/query">https://sandbox.safaricom.co.ke/mpesa/accountbalance/v1/query</a> for testing purposes.</p>
</li>
<li>
<p><strong>What is the difference between the different account types in the result?</strong></p>
<ul>
<li>Utility Account: Receives pay bill payments.</li>
<li>Merchant Account: Receives buy goods or till payments.</li>
<li>Working (MMF) Account: Holds money awaiting settlement.</li>
<li>Charges Paid Account: Deducts charges incurred based on the business tariff.</li>
<li>Organization Settlement Account: After charges are deducted, money passes here to the working account.</li>
</ul>
<p><strong>Q: What should I do if I do not receive a response?</strong><br>
<strong>A:</strong> Check the QueueTimeOutURL for timeout notifications and ensure your ResultURL is correctly configured and reachable.</p>
</li>
<li>
<p><strong>Are there any usage limits for the API?</strong><br>
Safaricom may impose rate limits on API usage to ensure fair usage and system stability. Check the API documentation or contact Safaricom support for details on any applicable rate limits and best practices for optimizing API usage.</p>
</li>
<li>
<p><strong>Can I request the balance of another shortcode?</strong><br>
