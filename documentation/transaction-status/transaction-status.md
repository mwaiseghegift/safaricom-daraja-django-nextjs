class="docs_tableContainer__qBw9Z MuiBox-root css-1oyv9ht"><h2 id="overview">Overview</h2>
<p>The Transaction status API can be used as a secondary reconciliation mechanism when Callbacks are not received. To check the status of a transaction, you are required to have either an M-Pesa Receipt number or an Originator Conversation ID of the transaction.</p>
<h2 id="how-it-works">How It Works</h2>
<p>Organization sends the API request to check the status of an M-PESA transaction to Daraja, Daraja Authenticates the API call and pushes the request to M-PESA system. MPESA checks transaction status and responds to Daraja with the status. Daraja pushes the response back to the organization.</p>
<blockquote>
<p><strong>Note:</strong> This API is asynchronous and can be consumed over the internet, VPN, or Multiprotocol Switch.</p>
</blockquote>
<h2 id="getting-started">Getting Started</h2>
<h3 id="prerequisites">Prerequisites</h3>
<ol>
<li>Create a Daraja Account on <a href="https://daraja.safaricom.co.ke/">Safaricom Developer Portal</a>.</li>
<li>Create a sandbox app in the portal to get API credentials.</li>
<li>Retrieve Consumer Key &amp; Consumer Secret from your sandbox app on <a href="https://daraja.safaricom.co.ke/dashboard/myapps">My Apps</a>.</li>
</ol>
<h3 id="good-to-know">Good to Know</h3>
<p>This API is asynchronous. This API is used to check the status of a customer to business, business to business, Business to customer, Reversal and IMT transactions that happen on M-PESA.</p>

<h2 id="account-types-in-c2b-organization">Account Types in C2B Organization</h2>
<ol>
<li>
<p><strong>MMF/WORKING/M-PESA ACCOUNT FOR ORGANIZATION</strong></p>
<ul>
<li>When an organization wants to make a business withdrawal, the funds are transferred to this account before the withdrawal request is made.</li>
</ul>
</li>
<li>
<p><strong>UTILITY ACCOUNT</strong></p>
<ul>
<li>Payments from customers are credited into the utility account.</li>
</ul>
</li>
<li>
<p><strong>CHARGES PAID ACCOUNT</strong></p>
<ul>
<li>For payments received from customers, depending on the tariff, a charge is levied on the Organization or is split between the organization and the customer. The charges paid account is debited and always accrues a negative balance which has to be settled before an organization can make a withdrawal request.</li>
</ul>
</li>
<li>
<p><strong>ORGANIZATION SETTLEMENT ACCOUNT</strong></p>
<ul>
<li>This account does the calculations for the organization operator when s/he initiates a revenue settlement. This account settles the charges paid account and then moves the balance from the Utility Account to the MMF account automatically. You will notice that the transaction type “Move funds from Utility to MMF” is no longer available as the revenue settlement process takes care of this.</li>
</ul>
</li>
</ol>

<p><strong>How do I generate Security Credential?</strong></p>
<ul>
<li>M-Pesa Core authenticates a transaction by decrypting the security credentials. Security credentials are generated by encrypting the base64 encoded initiator password with M-Pesa’s public key, a X509 certificate.</li>
<li>The algorithm for generating security credentials is as follows:
<ul>
<li>Write the unencrypted password into a byte array.</li>
<li>Encrypt the array with the M-Pesa public key certificate. Use the RSA algorithm, and use PKCS #1.5 padding (not OAEP), and add the result to the encrypted stream.</li>
<li>Convert the resulting encrypted byte array into a string using base64 encoding. The resulting base64 encoded string is the security credential.</li>
</ul>
</li>
</ul>
</li>
