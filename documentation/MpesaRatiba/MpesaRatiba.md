    <ol>
        <li style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">Knowledge of RESTful principles and JSON.</li>
        <li style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">Understanding Asynchronous processing and callback handling.</li>
        <li style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">Set up an App on Daraja to be used for testing on the simulator. Ensure to select "M-Pesa Ratiba" when creating the app</li>

    <p style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">M-PESA Ratiba API is an extension of the Safaricom Standing order functionality that will allow third party integrators to avail this functionality to their users.</p>
    <p style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">(STK Push/NI push) is a Merchant/Business initiated prompt, that will allow M-Pesa user to enter their pin for authentication and user validation purposes.</p>
    <p style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">Once you, our merchant integrate with the API, you will be able to send a pin prompt on the customer's phone (Popularly known as STK Push Prompt) to your customer's M-PESA registered phone number requesting them to enter their M-PESA pin to authorize, and continue with the rest of the journey involving opt in and creating a standing order.</p>
    <br>
    <h2 style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">High Level user flow</h2>
    <ul>
        <li style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">A user will probably interact with the integrated API through the merchant’s digital channel, could be a web interface or an app interface. The user will enter the standing order details, including the name, amount, start date, end date, etc. – (As per the merchant’s configurations on the digital channel.)</li>
        <li style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">The merchant channel, through the API will send the data to our systems. Here we will run the authentication checks through our gateway. Once authenticated, we will initiate an NI push to the M-Pesa user. The user will enter their pin. This will be consent to proceed with all operations coming after and also validate ownership of the MSISDN.</li>
        <li style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">We will run a check to see if the user is opted in, if not, we will opt the user in. If the user is opted in, we will proceed with the request to create a standing order.</li>
        <li style="margin: 0cm 0cm 0.0001pt; font-family: Calibri, sans-serif; line-height: 1.5; font-size: 16px;color: rgb(0, 0, 0)" ;="">We will then send a callback to the merchant, with the status of the process, the transaction code and the unique response id</li>
    </ul>
